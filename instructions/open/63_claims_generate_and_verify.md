# 63 · Claims: generate knowledge with a calibrated certainty, then test it independently

The user's goal (2026-10-04), in their words: Starplast should (1) generate new knowledge from existing
data and (2) test that knowledge in ways separate from the inference that generated it, both in the flow
of the program, easy and intuitive: "generate relevant knowledge with a certainty score, then test that
knowledge to make sure it's actually true". Once that is reliable and quantified, apply the strategies
known to work genome-wide.

## Evidence that this works (measured 2026-10-04 on the shipped track record, Tg compartment)

* **Support is calibratable.** kNN's support, in fifths: right 32%, 36%, 44%, 57%, 69% of held-out genes.
* **Independent agreement separates true from false.** kNN's call, checked by a strategy on other evidence:

  | Verifier | kNN right overall | verifier agrees -> right | disagrees -> right |
  |---|---|---|---|
  | physical partners (XL-MS / IP-MS) | 0.52 | 0.85 | 0.30 |
  | shared fold (structure) | 0.45 | 0.70 | 0.33 |
  | label diffusion (coexpression) | 0.48 | 0.61 | 0.46 |

  The more disjoint the evidence, the stronger the test: coexpression overlaps kNN's features and helps
  least.

## The design

### The unit: a claim
`gene · label · value · certainty · generated by (strategy, evidence families) · verdicts`.
One table (`claims.py`), the same everywhere it appears: gene card, a Discoveries view, exports.

### Step 1 — certainty that means what it says
Map each (organism, label, strategy) support to the empirical precision of held-out calls with that
support (isotonic, from the track record), with an interval. "Certainty 0.85" must mean "85 of 100 such
calls were right when the answer was hidden". Report calibration error per strategy; a strategy whose
certainty is not calibrated is not used to generate claims.

### Leakage is measured, never assumed (user, 2026-10-04)
"Information leakage needs to be quantified not guessed": a signal peptide is location information
though it shares no dataset with LOPIT. Two measurements, both from held-out genes:

1. **Generator vs verifier: the shared-mistake ratio.** Among genes the generator gets wrong, how often
   the verifier makes the SAME wrong call, over how often it would if the two were independent given
   the truth (from the verifier's own confusion matrix). 1.0 = independent. Measured 2026-10-04, Tg
   compartment: kNN vs physical partners 1.2x, vs shared fold 1.2x, vs label diffusion (coexpression)
   1.9x, vs random forest 3.5x; classifier vs random forest 3.8x. Bootstrap interval over genes. A
   verifier counts as an independent test only below a set ratio (upper bound of the interval).
2. **Evidence vs label: circularity.** Per evidence family, how much of the label that family alone
   recovers, and whether that differs between labels assigned by experiment and labels assigned by
   prediction (`compartment_source` records which). A family that recovers predicted labels far better
   than measured ones is restating the predictor, not measuring biology.

The combined certainty never assumes independence: it is fit on held-out genes from the measured
agree/disagree outcomes, so any dependence the ratio misses is still priced in.

### Step 2 — independent verification
* Dataset bookkeeping (`datasets.provenance`, `search.LAYER_SOURCES`) is a first screen only: kNN's
  features include crosslink-, IP-MS- and Foldseek-derived counts (`n_xlink_partners`,
  `n_ipms_partners`, `n_struct_similar`), so even "physical partners" is not disjoint by datasets.
* A verifier is **eligible** for a claim only if its measured shared-mistake ratio with the generator
  is low (above).
* Each (generator, verifier) pair gets a measured **lift** from the record: P(right | agrees) and
  P(right | disagrees) on the same held-out genes (as in the table above). The verdict on a claim is
  then quantified: certainty after agreement / after disagreement, not a checkmark.
* Combine several independent verdicts (naive-Bayes on measured likelihood ratios, checked on the record
  for over-confidence; fall back to the single best verifier if combining is not calibrated).

### Step 3 — prospective tests (the strongest kind)
Freeze claims with a version and hash. When a dataset is added later (a new screen, a new LOPIT), score
the frozen claims against it automatically. That is a test the generator could not have seen.

### Step 4 — proven recipes, genome-wide
A recipe = (label, generator, verifiers, certainty threshold) whose certainty is calibrated and whose
verified precision at the threshold is measured with n >= 30. Run every proven recipe over every
unlabelled gene: the Discoveries view lists claims by certainty after verification, condensed, each
clicking to its evidence and the generator's record for that class.

### The flow (condensed first, click deeper)
* Start here gains "What don't we know yet?" -> proven recipes -> claims.
* Gene card: "Starplast's claims for this gene" with certainty and ✓/✗ from independent checks.
* Every claim -> why (generator, evidence) -> how it was tested (verifiers, lift) -> track record.

## Traps
* A verifier that shares a dataset with the generator is not independent, whatever its name.
* Calibrate per label and per class where n allows; a pooled curve hides rare classes.
* Certainty learned on held-out genes is for genes LIKE them; unlabelled genes are often understudied.
  Report calibration separately for the understudied stratum (`stratum_focus` already defines it).
* Never show an uncalibrated number as a certainty.
