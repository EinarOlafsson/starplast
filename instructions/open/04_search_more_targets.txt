================================================================================
RUN THE STRUCTURE SEARCH AGAINST THE TARGETS THAT WERE ACTUALLY ASKED FOR
================================================================================

STATE
    search.py works and has been run exactly once, against `lopit_unified`:
    164 combinations, best mean F1 0.362, apical secretory best at 0.59.
    Results in data/structure_search.parquet.

    The user's stated goal was broader: "find structures where location maps
    well so we can infer location, or cell cycle stage maps well to the
    structure so we can infer when hypothetical genes are potentially active".
    Stage and cell cycle have never been searched.

WHY IT MATTERS
    This is the point of the project -- "a structural space nobody has
    exhaustively explored". The machinery is built and idle.

WHAT TO DO
    Targets worth searching, with the label source:
      - stage: toxo_stage_atlas/data/stage_proteomic_assignment.csv, consensus
        calls for 3,153 genes
      - the 23 curated canonical markers in markers_stage_toxoplasma.csv, as a
        positive control -- too few for enrichment statistics, ideal as a check
        that a real signal is recovered
      - attention_depth, as a NEGATIVE control: if a structure "recovers" how
        much a gene has been studied, the features encode study effort and the
        map is measuring the literature, not the biology
      - the new columns from expression.py open targets that did not exist
        before: in vivo chronic behaviour, stress response, MORC dependence

    Widen the grid too. The one run used 2 n_neighbors x 1 min_dist x 2
    min_cluster_size on a 3,000-gene sample. It took 706 s. A full-proteome run
    across a wider grid is hours, which is fine unattended.

HOW TO KNOW IT WORKED
    A ranked table per target, and for any structure that recovers a label
    well, `search.predictions()` turns it into named predictions for the
    unlabelled genes in each pure cluster.

TRAPS
    Check `excluded_for()` output for every new target before trusting a
    result. For lopit_unified it removed six columns; a target with more
    derivatives will need more removed, and the whole inference rests on that.

    The negative control matters as much as the positive one. If
    attention_depth is recoverable, say so loudly.
