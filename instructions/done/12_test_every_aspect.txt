TEST EVERY ASPECT OF THE LIBRARY, END TO END, WITH THE REAL DATA
================================================================================

STATE
    77 tests. They are good tests -- several caught real bugs before the bugs
    reached the app -- but they are not COMPLETE, and the gaps are not random.
    They cluster exactly where testing is awkward: the fetchers, the build,
    the app's interactive paths, and the long analysis walks.

    Measure it first. `pytest --cov=starplast --cov-report=term-missing` and
    write the per-module numbers into this file before starting, so the work
    is against a number rather than a feeling.

WHY IT MATTERS (the user's reasoning, and it is right)
    This program IS data. Nearly every function is a transformation from one
    table to another table, which is the easiest thing in software to test:
    feed it input, assert on output. There is no network in the hot path, no
    clock, no concurrency, no user state. A library shaped like this has no
    excuse for untested branches.

    And the failure mode here is silent. Every bug this project has hit --
    StringTie ids losing half a dataset, a two-row header collapsing 3,000
    proteins into one column, FPKM logged twice, additive blending, the
    circularity leak -- produced NO error. The code ran, the output looked
    plausible, the numbers were wrong. Tests are the only thing that catches
    that class, because looking at it does not.

WHAT TO DO

  1. RUN THE REAL DATA THROUGH THE WHOLE PIPELINE, AS ONE TEST
     The strongest test this project can have is the pipeline end to end on
     the committed cache, asserting the invariants that must hold at every
     stage:

        identity  -> every id resolves or is recorded as unresolved; no id
                     silently becomes NaN
        corpus    -> section counts stable; no caption counted twice
        literature-> mentions.parquet gene set is a subset of nodes
        screens/
        expression-> every joined dataset contributes >0 rows (the StringTie
                     bug WAS a dataset contributing 0 and nobody noticing)
                  -> column count per dataset matches the header parse (the
                     merged-header bug WAS 3,000 proteins in one column)
        embedding -> no all-NaN column; no constant column; variance shares
                     sum to 1
        clustering-> labels align with the matrix row order
        search    -> held-out labels really are held out (assert the excluded
                     set is absent from the input columns, measured not named)
        graph     -> node/edge ids reference existing genes; no self-edges;
                     symmetric where the edge type is undirected

     Mark it slow if it takes minutes; do not skip it by default.

  2. PROPERTY TESTS WHERE THE INVARIANT IS SHARPER THAN AN EXAMPLE
        normalise()      log-then-centre is idempotent under re-centring;
                         'ratio' and 'lfc' come back untouched
        rank_normalise() output range within [-0.5, 0.5]; ordering preserved;
                         NaN stays NaN
        infer_quant()    the two known traps pinned as regression cases:
                         real FPKM at 16,520 -> 'fpkm' (must be logged),
                         already-logged FPKM at 9.13 -> 'log_intensity'
                         (must NOT be logged again)
        depth_cue()      alpha and size monotone decreasing in distance;
                         degenerate case (all points equidistant) does not
                         divide by zero
        identity.find()  an accession span is never re-matched as a symbol

  3. THE BRANCHES THAT ONLY RUN WHEN SOMETHING IS WRONG
     Every `except`, every "unknown quantification", every "no RESULT files",
     every empty-input early return. These are the least-run and most-trusted
     lines in the repo. Test them with real inputs that trigger them, not with
     mocks that assert the mock was called.

  4. THE APP, HEADLESS
     QT_QPA_PLATFORM=offscreen already works -- test_gl_compat.py does it. So
     every control is testable: toggle each edge type, each theme, each colour
     mode, each point style, each LOD tier, pick a gene, clear the selection,
     open and accept Preferences. Assert on the resulting arrays AND on the
     item list, since the additive-blending bug passed every array assertion.

  5. NETWORK CODE WITHOUT NETWORK
     geo_supplementary() and pride_files() are the only network functions.
     Test the parsing against saved real responses (a captured GEO FTP listing
     and a captured PRIDE JSON, committed as fixtures), and test that a failed
     request returns empty rather than raising. Do not test that urllib works.

HOW TO KNOW IT WORKED
    100% COVERAGE, EVERY MODULE. Set by instruction on 2026-08-11; the earlier
    bar in this file was 90% and was raised.

    No `# pragma: no cover` used to reach the number -- a defensive branch is
    tested by making the defect actually happen, not by excusing the line. If a
    line genuinely cannot be reached, that is evidence the line should not
    exist; delete it rather than exempting it. The same rule spacr runs under.

    The real check: reintroduce any one of the five historical silent bugs
    listed above, and the suite goes red. Try it for at least two of them.

TRAPS
    Coverage percentage is not the goal and will mislead if it becomes one. A
    test that calls a function and asserts it returned something raises
    coverage and catches nothing. Every one of this project's real bugs was a
    WRONG VALUE, not an exception -- so assert on values.

    pytest-qt imports PySide6 at plugin load and pyqtgraph then binds to it
    while the app hard-imports PyQt6. PYQTGRAPH_QT_LIB=PyQt6 must stay pinned
    in tests/conftest.py.

    Do not let the end-to-end test depend on the network. It runs on the
    committed cache. If it needs a file that is not committed, that is a
    finding about the cache, not a reason to fetch.

    The raw datasets tree is not committed and not in the repo (see task 08),
    so a genuine raw->cache rebuild cannot run on a clean checkout. Decided:
    the always-on end-to-end test asserts invariants across the committed
    cache; the true rebuild is a separate opt-in test that SKIPS when the
    dataset root is absent and RUNS when task 08's resolver finds it. A skip
    must be loud enough to notice, or it becomes a test that never runs and
    everyone believes it does.

    100% is a much larger job than 90% and the last few percent are the GUI and
    the fetchers. Do them properly rather than by calling a function and
    asserting it returned something: every real bug in this project was a wrong
    value, not an exception, and a test that only raises coverage catches none
    of them.

WHAT THE TESTS FOUND

Nineteen bugs, every one of them silent. In rough order of severity:

  1. add_strain_accessions was wired into the literature path but NOT the
     node-column path, so every dataset keyed on a TGGT1_ accession joined zero
     rows -- and TGGT1_ is more common than TGME49_ in published supplements.
  2. The circularity guard could not see numeric columns at all: _assoc_impl
     compared categorical-to-categorical and continuous-to-continuous and
     skipped every mixed pair.
  3. ...and even fixed, a label that is a joint function of three columns is
     invisible to any pairwise measure, so declared provenance was needed too.
  4. `domain` edges: 31 self-edges and 106 duplicated pairs, because InterPro
     reports one row per MATCH and repeat families match many times.
  5. import_table extracted with an ME49-only pattern, discarding strain
     accessions BEFORE the identity layer saw them -- in exactly the case its
     docstring promised to handle.
  6. expression._norm_acc normalised '-' and '.' but the pattern never let those
     forms through, so three of the four mangled spellings resolved to nothing.
  7. embed() median-filled, but the median of an all-missing column is NaN, so
     one unparsed screen would kill the whole build with "Input contains NaN".
  8. build_matrix with drop_genes silently produced a 0-gene matrix.
  9. missingness_leak raised KeyError in exactly the case where the honest
     answer is "nothing leaks".
 10. walk_umap raised KeyError when every grid point was skipped.
 11. hf_publish.build_release raised KeyError on an empty licence table.
 12. screens._read raised out of pd.read_excel when a workbook lacked a sheet,
     taking the whole build down for one renamed tab.
 13. search passed min_cluster_size straight to HDBSCAN, which raises rather
     than returning all-noise, so one grid point ended a 328-run walk.
 14. The search progress line fired on `runs % 40 == 0` at a stride that only
     sometimes divides 40, so a twenty-minute walk could print nothing.
 15. The DOCX reader split every table row across two lines -- the same
     corruption its docstring says it prevents, in the other direction.
 16. The analysis panel's "nothing separated the clusters" message was
     unreachable: `+` binds tighter than `or`.
 17. The search tab's target list was hardcoded, so cellcycle_phase existed in
     the module and in the table and could not be chosen.
 18. open_preferences ended in exec(), so it could not be tested at all without
     hanging; construction is now split out.
 19. Absence labels were scored as classes -- see done/10, the one that changed
     a published number.

HOW THE HARD MODULES WERE DONE
    The loaders are tested against synthetic supplements with the same SHAPE as
    the real ones -- header on the second row, an accession column not called
    gene_id, a gene listed twice, a two-row merged header -- because the shape
    is what every historical bug was about, and the real files are not
    committed.

    build_graph gets a synthetic tree and one test that runs
    `python -m starplast.build_graph` for real over sixty genes, which also
    proves the resolver works for a fresh process rather than only for this one.

    The GUI runs headless against the real cache, asserting on the item list and
    on redraw ORDER as well as on the arrays -- three rendering bugs in this
    project passed every array-level assertion.

THE END-TO-END TEST
    tests/test_pipeline_end_to_end.py runs over the committed cache and asserts
    the invariants that hold ACROSS stages. It found bug 4 on its first run. The
    rebuild-from-source checks skip when the raw tree is absent and run when the
    resolver finds it -- verified both ways.

WHAT IS NOT TESTED, AND WHY
    Nothing is exempted. Two paths are marked `slow` rather than skipped: the
    real `python -m` build (~100 s) and the pdoc documentation pass. Run them
    with `pytest -m slow`.
